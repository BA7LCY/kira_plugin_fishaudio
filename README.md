# Fish Audio 语音

让大模型把回复转成 **Fish Audio 高质量语音** 的 KiraAI 插件：模型在回复里写一个 `<fish>` 标签，插件就会用你选好的音色把里面的文字念出来发到群里/私聊，还支持在文字里加情绪标记控制语气。

仅供参考：[Fish Audio 官方文档](https://docs.fish.audio/developer-guide/core-features/emotions)。

## 它怎么工作

模型回复里出现这样的内容：

```xml
<fish>[happy] 今天天气真好，一起出去走走吧！</fish>
```

插件会把 `[happy] 今天天气真好，一起出去走走吧！` 转成语音发出去：

- `[happy]` 这类方括号是**情绪标记**：Fish 只用它控制语气，不会把它念出来（上面这句会念成「今天天气真好，一起出去走走吧！」而不是「happy 今天天气真好…」）。
- 没写 `<fish>` 标签的普通回复照常发文字，不受影响。
- 想让某一句临时换音色，可以写 `<fish voice="音色ID">文字</fish>`；不写就用你在 WebUI 里设的默认音色。

**转语音文字上限**：标签里的文字超过一定字数就不转语音、直接发文字，避免一口气念一大段（默认 80 字，可在设置里改）。

## 快速开始

1. 把 `kira_plugin_fishaudio` 文件夹放进 KiraAI 的插件目录，在插件管理里启用。
2. 打开插件设置，在「Fish Audio 服务」里填 **API Key**（在 <https://fish.audio> 个人中心申请；Key 填错会合成失败，收到 401 报错）。
3. 打开插件页「Fish 音色库」，添加音色（填音色 ID 或整条音色页面地址）并「设为默认」；不设默认音色也可以用官方默认音色。
4. 告诉模型：需要发语音的回复用 `<fish>文字</fish>` 标签包起来。

## 配置说明

各配置项与插件设置页里的说明保持一致（默认值、可填范围、格式、填错会怎样）。

| 配置项 | 说明 |
| --- | --- |
| 基础 → 启用插件 | 关闭后 `<fish>` 标签不再转语音，直接发文字。默认：开。 |
| 基础 → 转语音文字上限 | 标签里的文字超过这个字数就不转语音、直接发文字，避免一口气念一大段。可填 1~500，默认 80；填 0 或负数会被自动改成 1。 |
| 基础 → 请求超时（秒） | 每次合成语音最多等多少秒，超时就放弃、发文字。可填 1~300，默认 30；填 0 会被自动改成 1。 |
| 基础 → 音频格式 | 合成出的音频格式。默认 mp3（体积小、兼容性好）；wav 音质无损但文件大；opus 更省流量。填别的值会自动用回 mp3。 |
| Fish Audio 服务 → API Key | 在 https://fish.audio 个人中心申请的 API Key，必填，否则 `<fish>` 标签只会发文字。Key 填错会收到 401 报错、合成失败。 |
| Fish Audio 服务 → 接口地址 | 一般不用改。用官方服务保持默认；自建代理填你的网关地址，例如 https://tts.example.com（结尾不用带 /v1/tts，插件会自动补）。填错会连不上服务、合成失败。 |
| Fish Audio 服务 → 合成模型 | s2.1-pro：效果最好的付费模型；s2.1-pro-free：免费但速度慢、不保证质量；drama-3：更适合角色扮演。填别的值会自动用回 s2.1-pro。 |
| Fish Audio 服务 → 兜底音色 ID | 音色库里没有设默认音色时，用它来合成。格式是音色页面地址末尾那串 32 位字母数字，例如 ca3007f96ae7499ab87d27ea3599956a，也可以直接贴整个音色页面地址。留空则用 Fish 官方默认音色。填错会导致合成失败。 |
| 情绪语气 → 识别情绪标记 | 开启后，文本里的 [happy]、[whispering] 这类方括号标记会原样发给 Fish，让它只改变语气、不会把标记念出来。关闭后标记会当普通文字念。默认：开。 |
| 情绪语气 → 标记范围 | any：任何方括号内容都当情绪标记；whitelist：只认 Fish 官方情绪清单加你下面自定义的标记。默认 any。 |
| 情绪语气 → 自定义标记（白名单模式用） | whitelist 模式下额外允许的情绪标记，用逗号分隔，例如：slightly happy, very angry。留空表示不加。 |
| 情绪语气 → 最多保留标记数 | 一句话里最多保留几个情绪标记，超出的一律丢掉。可填 0~20，默认 6；填 0 表示不保留任何标记。 |
| 情绪语气 → 发文字时剥离标记 | 当内容因为太长或合成失败降级发文字时，是否把 [happy] 这类标记从文字里去掉。默认：不去。 |
| 高级 → 语速 | 0.5~2.0，1.0 是正常语速，小于 1 变慢、大于 1 变快。默认 1.0；填超出范围的数会被自动收进范围。 |
| 高级 → 音量（分贝） | 相对音量的增减，单位分贝，可填 -24~24，默认 0（不调整）。 |
| 高级 → 随机性 temperature | 0~1，越大语气越随意。默认 0（保持稳定，且不发送这个参数给 Fish）。 |
| 高级 → 采样 top_p | 0~1，一般不用动。默认 0（不发送这个参数给 Fish）。 |
| 高级 → 延迟档位 | normal 最稳；balanced 首段语音更快；low 最快但可能降低音质。默认 normal。 |
| 高级 → 数字日期口语化 | 开启后 Fish 会把 2024、1234 这类数字按口语念出来。默认：开。 |
| 高级 → 失败重试次数 | 合成失败（网络波动、服务端 5xx）时最多重试几次。可填 0~3，默认 1；填 0 表示失败就放弃、直接发文字。 |
| 高级 → 附加请求字段（高级） | 以 JSON 形式附加到合成请求里的额外字段，例如 {"mp3_bitrate": 128}。一般不用填；填错格式会导致请求失败。 |

## 音色库（WebUI）

插件页「Fish 音色库」可以：

- **添加音色**：填名称（≤24 字）、音色 ID（音色页面地址末尾那串 32 位字母数字，或直接贴整条地址）、备注（≤60 字）。
- **试听**：先选音色再点「试听」，马上听到合成效果（默认文案可改）。
- **设为默认 / 取消默认**：插件合成时优先用这里设的默认音色；没设默认才用设置里的「兜底音色 ID」。
- **删除**：点删除后有 3 秒确认，防止误删。

> 音色库里最多存 50 个音色。

## 情绪标记

Fish S2 系列支持在文字里直接写方括号描述来控制语气，常见用法：

- 基础情绪：`[happy]` `[sad]` `[angry]` `[excited]` `[calm]` `[surprised]` `[confident]` `[grateful]` `[sarcastic]` 等
- 语气/音效：`[whispering]` `[shouting]` `[in a hurry tone]` `[laughing]` `[sobbing]` `[sighing]` `[clear throat]`
- 修饰强度：`[slightly sad]`、`[very excited]`（修饰词 + 情绪）
- 每句建议最多 3 个情绪组合

完整清单见 [Fish Audio 官方文档：情绪](https://docs.fish.audio/developer-guide/core-features/emotions)。

## 常见问题

- **发出来的还是文字，没有语音？** 检查：插件设置里有没有填 API Key；标签里文字是否超过「转语音文字上限」；插件有没有启用。
- **提示合成失败 / 401？** API Key 不对或余额不足，去 fish.audio 个人中心确认。
- **提示连不上服务？** 「接口地址」填错了，或网络不通。
- **不想让某次回复发语音？** 让模型不要用 `<fish>` 标签即可；也可以在设置里关掉「启用插件」整体停用。

## 开发

```
kira_plugin_fishaudio/
├── main.py                  # 插件入口：<fish> 标签、音色库 WebUI 与 API
├── manifest.json            # 插件清单
├── schema.json              # 配置定义（与 core/settings.py 的默认值同步维护）
├── requirements.txt         # 依赖：httpx
├── core/                    # 纯逻辑模块（零框架依赖，便于测试与迁移）
│   ├── emotion.py           #   情绪标记解析/归一化/剥离
│   ├── voice_library.py     #   音色库存储（原子写盘）
│   ├── tts_client.py        #   Fish TTS 客户端（httpx + 依赖注入）
│   └── settings.py          #   配置解析与边界钳制
├── web/                     # 音色库管理页面（原生 JS，无框架）
├── tests/                   # 测试
└── docs/                    # 内部开发记录（不进公开仓库）
```

**设计要点**

- 核心逻辑全部在 `core/`，不依赖 Kira 框架，可以脱离框架单独测试，也方便将来迁移到其他机器人框架。
- TTS 客户端支持依赖注入：测试时传入带 `MockTransport` 的假 httpx 客户端，不需要真实网络。
- 合成失败一律降级为发文字，绝不打扰用户。
- 音频缓存放在插件数据目录的 `tts_cache/` 下，会自动清理超过 1 小时的旧文件。

**运行测试**

需要本机有 Python 3.10+ 且已安装 httpx（`pip install httpx`），然后在插件目录执行：

```bash
python -m tests.run_all
```

装了 pytest 的话也可以直接 `pytest tests/`（测试写法兼容）。
